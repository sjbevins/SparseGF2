# Erasure enumeration and sampling cost

Recorded 2026-10-15 on AMD Ryzen 9 9950X3D 16-Core Processor (16 cores, 32 logical processors), Python 3.14.7, Numba 0.68.0, sparsegf2 3.0.0.dev11. Every time is **one thread**, after a warm-up; single-thread times are inflated directly by any background load. During the run the machine was otherwise idle except for background services, including a local LLM server (about 0.4 of one core when sampled before the run); background activity inflates single-thread times, so treat differences under about 10 % as noise.

Codes: Watts-Strogatz graphs (k = 4, beta = 0.1, one graph per trajectory), purification picture, `random_edges`, 4n layers, `code_snapshot` at the final layer; the first 8 trajectories with k > 0 per (n, p). Generated by `python benchmarks/erasure_cost.py`; total 20.2 min.

* **library**: `StabilizerCode.uncorrectable_counts(w)` or `first_failure_sizes(M)` on the saved code;
* **engine**: the trajectory rerun with R copies of the probe at its final layer, minus the same run without probes, divided by R (R makes the probes take about as long as the evolution; R = 1 for slow levels). The engine's counts equal the library's for every code (checked).

Medians and maxima are over codes. A time includes the fixed `code_columns` elimination that every evaluation pays.

The two paths run the same kernels, but the engine's fixed elimination costs more: it reduces the trajectory's tableau rows, while a saved code's normalizer rows arrive already reduced (`symplectic_complement`). At w = 1, almost all elimination, the engine took 2.1 to 4.0 times the library's time for n >= 128 (also visible in the first-failure rows at M = 100). From w = 4 on the walk dominates and the paths agree: engine / library 0.99 to 1.04.
