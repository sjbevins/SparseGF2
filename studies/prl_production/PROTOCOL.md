# Single-reference purification-time protocol

## Physics definition

For a system of `n` qubits, the simulator contains `n+1` qubits.  System
qubit `n-1` and reference qubit `n` begin in a Bell pair; the remaining
system qubits begin in `|0>`.  The reference is never gated or measured.
Consequently its entropy is binary,

```text
S(R, T) in {0, 1}.
```

For each trajectory we define

```text
tau_p = min { T in {1, ..., 8n} : S(R, T) = 0 }.
```

`S(R)` is evaluated after the gates and measurements of every measured layer,
including layers with no measurements.  The trajectory stops at its first zero.
If `S(R, 8n)=1`, the observation is right-censored: `tau_p` is missing,
`stop_layer=8n`, and `event_observed=0`.  A zero first reached at layer
`8n` is an observed event and is distinguished by `event_observed=1`.

## Circuit ensemble

- Interaction geometry: Watts-Strogatz rewiring of the circulant `C(n,2)`.
  Every realization has exactly `2n` edges and mean degree four.
- Disorder: one independently seeded graph realization per trajectory.
- Initial scramble: 32 layers of random all-to-all perfect matchings, with a
  uniformly sampled element of `Sp(4,F_2)` on every pair.
- Measured layer: sample `n/2` graph edges uniformly with replacement, apply
  independent uniform `Sp(4,F_2)` gates in sampled order, then measure every
  system qubit in `Z` independently with probability `p`.
- Depth cap: `T_max=8n` measured layers.  Scramble layers are not counted in
  `T`.
- Execution: the phase-free sparse/dense hybrid tableau and ordered batch
  kernels.  Tests require exact equality with scalar execution.

Measurement outcomes do not affect a phase-free tableau, but their random
draws are still consumed in the same order as scalar execution.  Independent,
tuple-keyed streams are used for graph construction, gate placement,
measurement selection/outcomes, and scrambling.  Adding a new value of `p`
or `beta` therefore cannot perturb any existing trajectory.

Each run directory is keyed by a SHA-256 fingerprint of the SparseGF2 Python
sources, production engine, steering inputs, interpreter, NumPy, and Numba.
Results generated by different code or numerical environments therefore cannot
be mixed by resume.  A process lock also prevents two live runners from writing
the same point concurrently.

## Production grid

The planned production sizes are

```text
n = 32, 48, 64, 96, 128, 160, 192, 256.
```

There are 500 trajectories per `(n, beta, p)`, one per graph index.  The beta
grid and preliminary transition centers are in
`inputs/refinement_centers.csv`.  Centers only steer where simulations are
dense; they are never supplied to the final fit.  For every beta, the default
grid has spacing `dp=0.001` across `p_center +/- 0.040`, plus outer guard
points.  The broad window deliberately contains the visibly anomalous
near-`beta=0.026` preliminary estimate rather than assuming it is physical.

Before the production launch, the dry-run manifest states the exact number of
points and trajectories.  The campaign is resume-safe at the individual graph
trajectory level.

## Stored data

Each point file contains fixed-length arrays:

- `tau_p`: exact first-zero layer, or `-1` when censored;
- `stop_layer`: first-zero layer or the cap;
- `event_observed`: one for an observed first zero, zero for censoring;
- `complete`: per-trajectory completion marker;
- `graph_index`: the graph realization index.

Graph banks store the exact edge list for every realization.  Optional entropy
traces are restricted to audit/smoke runs; production evaluates `S(R)` every
layer but stores the sufficient first-passage and censoring data to avoid tens
of gigabytes of redundant binary traces.
