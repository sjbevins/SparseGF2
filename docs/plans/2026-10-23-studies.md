# Config-driven studies: implementation plan

**Spec:** [docs/specs/2026-10-23-studies-design.md](../specs/2026-10-23-studies-design.md) (what a study is, the
rulings R1-R12, the phases).

**Goal:** the SmallWorldMIPT survey framework, as it is, as `sparsegf2.study` with `sparsegf2 study ...`: one JSON
config to plan, run, grow, verify, draw and analyze a study of monitored circuits.

**Status:** deferred by the owner (2026-10-23); scope limited to what the survey framework does today (spec R3, R4,
R6, R8). Tasks below that go beyond it (other graph families or probes, MCP tools) are dropped until the owner asks.

**Execution (when resumed):** one task at a time, tests first; every check passes before a task ends; a push to branch
`studies` after each task (merged into `main` only when the owner says).

## Global constraints

- `python -m pytest`, `ruff check src tests`, `ruff format --check src tests` and `python -m mypy` (Success) pass after
  every task.
- No edit to `mipt.py`, `graphs.py` or `_kernel/` (R2); the randomness contract stays 2.
- American English everywhere (the spelling test).
- Commits are authored by the owner alone (no co-author trailers).

## Phase 1: the core

1. `study/options.py`: `Opt`, `REQUIRED`, checks, merging with defaults, unknown keys with suggestions, Markdown and
   plain-text documentation from the declarations. Tests: defaults, errors, suggestions, documentation.
2. `study/laws.py`: the Watts-Strogatz bank laws (vertex-major and offset-major; a verbatim port of the bank sampler
   with its seed words), and `study/points.py` (beta lists, theta grids, irrational anchors). Tests: the bank's graphs bit for bit
   (fixture), simple graphs with 2n edges, `m = 0` gives the ring.
3. `study/config.py`: the schema (study, location, graphs, points, sampling, sizes, rates, depth, circuit, record,
   seeds, run, plots, analyses) on `options`; rate grids (lists, ranges as decimal strings); depth laws. Tests: the
   template validates; every error message names the key.
4. `study/store.py`: segments, first passages, change-point runs, locking, reading dense arrays. Tests: round trips,
   extension segments, rerecord.
5. `study/engine.py`: the engine record (kernel fingerprint, engine modules, Clifford tables, libraries), taken at
   import (R7). Tests: stable within a process; refusal of a different id.
6. `study/plan.py`: conditions, targets, work per condition. Tests: new, rows, extend, rerecord, shrinking needs nothing.
7. `study/run.py` and `study/progress.py`: chunks through `MonitoredCircuit`, extension with the check against stored
   layers, a progress display that does not jitter, a worker process. Tests: a tiny study end to end; resuming after
   an interruption gives identical data; thread count does not change results.
8. CLI `sparsegf2 study plan|run|status|verify|config|options` with `--json`; `docs/STUDIES.md`. Tests: the CLI on a
   tiny study; the docs test.
9. Reproduction of the survey (R10): a fixture of survey trajectories, compared bit for bit.

## Phase 2: figures

10. `study/plots/`: the options of every kind (`heatmap`, `condition`, `curves`), text style (LaTeX, `prl`), the
    manifest; `study plot`. Tests: each kind draws on a tiny study; up-to-date figures are not redrawn.

## Phase 3: analyses

11. `study/fss.py`: the loss with linear parameters, landscapes, refits, systematics, crossings, extrapolations. Tests:
    synthetic data with known parameters are recovered.
12. `study/analyses/onset.py`: the onset analysis with every version and its report; `study analyze`, `study all`.

## Phase 4: adoption

13. Mixture sampling (ported with the core if simpler); `study adopt` for the survey's data folders; sweep marked as
    the older path in the docs; AGENTS.md.
